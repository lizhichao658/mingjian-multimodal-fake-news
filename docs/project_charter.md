# 明鉴项目章程 v1.1

## 1. 目标

构建一个可复现、可解释、可演示的多模态虚假新闻辅助研判系统。第一版处理新闻文本 + 单张图像，输出真假概率、风险等级、文本/图像证据、图文证据方向卡和人工复核提示。

## 2. 用户

- 内容审核员：筛选高风险内容，进入人工复核。
- 事实核查人员：查看模型关注的文本片段和图像区域。
- 普通用户：了解可疑内容的风险、证据和不确定性。
- 开发者/研究者：复现训练、评测、解释和审计流程。

## 3. MVP 范围

已在当前 lite MVP 中完成：

- 文本 + 单图输入，支持缺图降级；
- Weibo17 本地数据适配器、字符分词器和 PyTorch 数据管线；
- 自包含 TextCNN + ImageCNN + 门控融合 baseline；
- 真实数据训练、验证、测试和阈值调优；
- 文本梯度证据、图像 Grad-CAM、模态贡献输出；
- 图文证据方向卡：`证据同向 / 方向冲突 / 证据不足`；
- 证据卡真实分布审计脚本；
- 无 API Key 本地工作台和历史记录；
- 模型卡、数据卡、复现说明和测试。

明确不在第一版验收范围：

- 语义级图文一致性评分；
- 事实冲突对、外部事实检索或自动定罪；
- 视频、音频、OCR 全链路；
- 深度伪造检测；
- 批量导出、数据库持久化和多用户权限；
- 大规模爬虫与实时舆情监控。

## 4. 成功标准

- 从数据到训练、推理、解释和界面的最小闭环可运行；
- 关键指标与训练日志可追溯，不编造结果；
- 测试覆盖数据/模型、端到端推理、缺图降级和证据卡三态；
- 提供无 API Key 的演示路径；
- Git 提交细粒度；官方要求至少三条 Prompt 链，当前保留四条（含 v1.1 证据卡改造链）；
- 对过拟合、校准不足、单数据集域限制和证据卡阈值启发式进行明确披露。

## 5. 约束

- 单人开发，优先小闭环和可复现。
- 不得复制 ComP 或其他开源项目源码。
- 第三方模型、数据与论文必须声明。
- 原始数据、图片和权重不进入 Git。
- “证据同向 / 方向冲突”不得写成语义一致性、事实核验或因果证明。
- 所有高风险结论必须有人工复核提示。
