## 1. 初始意图

### 1.1 原始 Prompt（本人关键原句，按对话留痕整理）

```text
项目名：明鉴
第一版范围：文本 + 单图。
只用 Weibo17 就行。
ComP 代码仅仅作为参考思路，论文上没有代码，我们自己写。
严禁直接使用已有开源项目包装参赛。
我一个人作为一个队伍。
按 MVP 推进。
```

### 1.2 我的真实诉求

- 不把项目做成只有论文结构、没有可运行代码的“设想稿”；
- 不因追求论文级 SOTA 而拖垮第一版交付；
- 不做视频、音频、OCR、知识库或商业平台；
- 数据只用 Weibo17；
- 所有参考项目只提供问题意识和背景，不复制实现；
- 在比赛截止前形成“能跑、能解释、能录视频、能复现”的闭环。

---

## 2. AI 建议（人类读取后执行裁剪）

AI 给出的主要建议：

1. 第一版输入固定为“新闻文本 + 一张可选图片”，输出概率、风险等级、文本证据、图像热图、模态贡献和缺图降级；
2. 视频、音频、OCR、多图、外部检索、图文冲突分数、批量工作和数据库持久化全部移出 MVP；
3. 在“预训练双塔”和“自包含 lite 模型”之间，考虑当前网络受限、HF 缓存为空、8 GB 显存和 10 分钟复现要求，优先做自包含 lite；
4. 字符级 TextCNN + 小 CNN + 门控融合足以先形成真实闭环；
5. Web 端不强行依赖 FastAPI；如果环境没有安装，用 Python 标准库 HTTP 服务，保证无 API Key 也能演示；
6. 解释器只声明梯度归因和 Grad-CAM，不把热图写成因果证明；
7. 先写数据契约、标签契约和测试，再写模型和页面。

---

## 3. 人工决策

### 采纳

- 采纳“文本 + 单图”输入边界；
- 采纳“自包含 lite 模型优先”的工程路线；
- 采纳“解释器 + 本地工作台 + 真实训练”的闭环目标；
- 采纳标准库 HTTP 服务，避免现场缺少 FastAPI/uvicorn；
- 采纳“只使用 Weibo17”的数据边界；
- 采纳“模型输出只是辅助研判”的人机边界。

### 不采纳

| AI 或备选建议 | 不采纳原因 |
|---|---|
| 第一版直接上预训练文本/视觉编码器 | 需要下载，当前网络与缓存不可控，不利于离线复现 |
| 把图文冲突通道列为 MVP 必交项 | 会增加数据和解释链复杂度，当前无法给出经过验证的冲突证据 |
| 做批量检测、权限、数据库 | 不是第一版核心闭环，容易挤占文档和视频时间 |
| 直接参考 ComP 补齐模块 | 违反“不复制已有开源项目包装参赛”的边界 |
| 把高指标写在 README 作为宣传 | 没有真实运行证据前不得写入指标 |

### 人工补充约束

- 任何指标必须来自真实运行；
- 过拟合、ECE 偏高和阈值不稳定必须写入模型卡和报告；
- 原始数据、图片、完整 ID 和模型权重不得进入 Git；
- 远程仓库推送前必须做数据泄露与原创性检查。

## 6. AI 建议被拒绝后的结果

- 没有加入冲突评分和批量平台后，第一版在有限时间内完成了真实训练、解释器和页面闭环；
- 没有强行接入预训练权重后，基础测试不依赖网络，符合“10 分钟极速复现”的基础路径；
- 没有把指标包装成 SOTA 后，文档能够如实呈现校准和泛化风险。

---

## 7. 风险与下一步

- **风险 1**：MVP 的模型容量有限，跨域泛化不能从当前指标推断；
- **风险 2**：页面功能已有演示闭环，但历史记录仍只在内存中；
- **下一步**：补依赖锁、干净环境实测、PDF 技术文档和演示视频；
- **不进入下一步的事项**：未经消融验证的冲突通道、未评估的外部 API、未定义的批量权限系统。

---

## 8. 结论

本链完成的是“从大问题到小闭环”的意图控制：人工先锁范围，AI 给出实现路径，人工再拒绝不现实或不合规的部分。MVP 已完成，当前最重要的不是继续扩展功能，而是把过程证据整理成评委可复现的材料。
